# Сайт NEXORA: запуск и настройка

В папке находятся страница сайта `index.html` и сервер `nexora-server.mjs`. На сайте можно создать аккаунт по нику и паролю, необязательный email не подтверждается. Сервер также обеспечивает вход и чат поддержки с отдельными обращениями пользователей. Оплата поддерживает Crypto Pay через серверный секрет `CRYPTO_PAY_API_TOKEN`; статус заказа подтверждается подписанным webhook.

## Запуск на своём компьютере

1. Установите Node.js версии 24 или новее.
2. Откройте PowerShell в этой папке: `C:\Users\kalak\Documents\Codex\2026-10-19\ghdb\outputs`.
3. Задайте почту администратора и уникальный пароль длиной не менее 14 символов:

```powershell
$env:NEXORA_ADMIN_EMAIL = "ваша-почта@example.com"
$env:NEXORA_ADMIN_PASSWORD = "придумайте-уникальный-пароль-длиннее-14-символов"
node .\nexora-server.mjs
```

Не публикуйте пароль и не отправляйте его в чат.

4. Пока окно PowerShell открыто, откройте в браузере [http://127.0.0.1:8787](http://127.0.0.1:8787). Не запускайте `index.html` двойным щелчком: серверные функции не будут работать.
5. Войдите под ником `Администратор` и паролем из `NEXORA_ADMIN_PASSWORD`. На странице «Поддержка» появится список обращений; выберите пользователя, чтобы прочитать и ответить.

При первом запуске сервер создаёт администратора и файл базы данных `nexora.sqlite` в этой папке. Существующие аккаунты сохраняются. Новые пользователи регистрируются по нику и паролю; email в форме необязателен, не проверяется и не используется для восстановления пароля. Пароль должен содержать от 10 до 128 символов.

## Публикация для других пользователей

Для постоянной публикации подготовлена конфигурация Render в `render.yaml`. Бесплатный тариф для этого проекта не подходит: бесплатный сервис засыпает, а его файловые данные, включая SQLite, теряются при перезапуске. Нужен платный Web Service с постоянным диском; Render указывает цену диска отдельно, а актуальную стоимость самого сервиса показывает при создании. [Ограничения бесплатного плана](https://render.com/docs/free), [постоянные диски](https://render.com/docs/disks).

1. Создайте приватный репозиторий GitHub и загрузите в него содержимое этой папки: `index.html`, `nexora-server.mjs`, `package.json`, `render.yaml` и `.gitignore`. Не загружайте `nexora.sqlite`, `nexora.sqlite-wal`, `nexora.sqlite-shm` или пароли. Файл `.gitignore` исключает базу и `.env`.
2. В Render выберите **New → Blueprint**, подключите репозиторий и создайте сервис по `render.yaml`. Blueprint выбирает Node Web Service, платный план Starter, постоянный диск `/var/data` и путь базы `/var/data/nexora.sqlite`.
3. В Render откройте сервис → **Environment** и добавьте секреты `NEXORA_ADMIN_EMAIL` и `NEXORA_ADMIN_PASSWORD`. Пароль должен быть уникальным, не короче 14 символов. Сохраните настройки и дождитесь успешного deploy.
4. Откройте выданный Render адрес вида `https://nexora-site.onrender.com`. Сертификат HTTPS Render выдаёт автоматически. Для собственного домена его можно подключить позже.

Данные базы сохраняются на подключённом диске при перезапусках и новых публикациях, но всё равно периодически скачивайте резервную копию. Существующая база с локального компьютера автоматически не переносится: новый облачный сервис начнёт с новой базы. Сервис доступен, пока оплачиваются выбранный план и диск; «навсегда» без оплаты и резервных копий хостинг гарантировать не может. Render требует, чтобы публичный Node-сервис слушал `0.0.0.0` и порт из `PORT`; сервер сайта уже читает обе настройки из окружения. [Инструкция Render по Node-сервису](https://render.com/docs/web-services).

В профиле отображаются UID аккаунта, роль, даты регистрации и последнего входа, активные подписки, заказы и статус HWID. Браузер не может определить HWID: игровому клиенту нужна отдельная интеграция с сервером.

После изменения переменных окружения перезапустите сервер. Открывайте сайт через http://127.0.0.1:8787, а не двойным щелчком по HTML-файлу.

## Подключение оплаты Crypto Pay

1. В Telegram откройте `@CryptoBot` → **Crypto Pay** → **My Apps** и создайте приложение. Скопируйте именно **API token приложения Crypto Pay**. Обычный токен бота от `@BotFather` не подходит. Если токен уже публиковали в чате или вставляли в репозиторий, отзовите его и создайте новый.
2. В Railway → сервис сайта → **Variables** добавьте переменную `CRYPTO_PAY_API_TOKEN` со значением API-токена. Не добавляйте секрет в GitHub, HTML или сообщения. Сохраните переменную и дождитесь нового deploy.
3. В настройках приложения Crypto Pay укажите webhook URL: `https://nexora-production-9548.up.railway.app/api/payments/crypto/webhook` и включите событие `invoice_paid`.
4. После этого в магазине появится переход к созданию Crypto Pay-счёта. Сервер принимает статус только с корректной подписью Crypto Pay и сверяет сумму/валюту с заказом.

После подписанного уведомления Crypto Pay сервер сразу добавляет доступ к купленным клиенту/Premium/комплекту в аккаунт, без отправки письма. Поскольку в магазине не задан срок, платные доступы бессрочные и не продлеваются автоматически. «Сброс HWID» остаётся услугой, которую обрабатывает поддержка. Бесплатная тестовая подписка оформляется отдельным заказом за 0 ₽: заказ сохраняется в аккаунте, подписка действует 7 дней и доступна один раз на аккаунт. Для бесплатного заказа токен Crypto Pay не требуется. В профиле HWID останется «Не передан игровым клиентом», пока не появится отдельная интеграция с игровым клиентом.

Railway автоматически собирает новые коммиты ветки main, когда включён Auto Deploy для сервиса.
